# 기능 목록 / 유저 스토리

기능 ID는 커밋 메시지와 테스트 이름에 사용한다. 예: feat(F-01): 회원가입 구현

| ID | 기능 | 권한 | 화면 |
|---|---|---|---|
| F-01 | 회원가입 | GUEST | S-02 |
| F-02 | 로그인 / 로그아웃 | GUEST / USER | S-03 |
| F-03 | 게시글 목록 | 전체 | S-01 |
| F-04 | 게시글 상세 | 전체 | S-04 |
| F-05 | 게시글 작성 | USER | S-05 |
| F-06 | 게시글 수정 | 작성자 | S-06 |
| F-07 | 게시글 삭제 | 작성자 | S-04 |
| F-08 | 댓글 작성 | USER | S-04 |
| F-09 | 댓글 삭제 | 댓글 작성자 | S-04 |

권장 구현 순서: 공통 골격 → F-01 → F-02 → F-05 → F-03 → F-04 → F-06 → F-07 → F-08 → F-09

------------------------------------------------------------

## F-01 회원가입
유저 스토리: 방문자로서, 계정을 만들고 싶다. 왜냐하면 글을 쓰고 싶기 때문이다.

상세 동작
- 입력: 이메일, 비밀번호, 비밀번호 확인, 닉네임
- 성공 시 로그인 페이지로 이동하고 "가입이 완료되었습니다" 메시지 표시

검증 규칙
- 이메일: 필수, 이메일 형식, 최대 100자, 중복 불가
- 비밀번호: 필수, 8~20자, 영문+숫자 포함
- 비밀번호 확인: 비밀번호와 일치
- 닉네임: 필수, 2~10자, 중복 불가

예외 상황
- 검증 실패 / 중복 시 입력값(비밀번호 제외)을 유지한 채 해당 필드 아래에 오류 메시지 표시
- 중복 검사는 가입 전에 SELECT로 확인하고, 동시에 가입하는 경우를 대비해
  DB UNIQUE 제약 위반(DuplicateKeyException)도 잡아서 같은 메시지로 처리한다
- 이미 로그인한 사용자가 접근하면 목록(/)으로 이동

완료 조건
- [ ] 정상 가입 시 member 테이블에 BCrypt 암호화된 비밀번호로 저장된다
- [ ] 이메일/닉네임 중복 시 가입되지 않고 메시지가 표시된다
- [ ] 각 검증 규칙 위반 시 메시지가 표시된다

------------------------------------------------------------

## F-02 로그인 / 로그아웃
유저 스토리: 회원으로서, 로그인하고 싶다. 왜냐하면 회원 기능을 쓰기 위해서다.

상세 동작 (Spring Security 없이 직접 구현)
- 로그인: LoginController가 처리
  1) MemberRepository로 이메일 조회
  2) 비밀번호 비교
  3) 성공 시 사용자 정보들을 LoginMember 이름으로 세션에 저장(비밀번호 제외)
  
- 로그인 필요 페이지에 비로그인으로 접근하면 LoginCheckInterceptor가
  /login?redirectURL={원래 주소} 로 보낸다
- 로그인 성공 시 redirectURL로 이동, 없거나 안전하지 않으면 목록(/)으로 이동
  (안전한 주소 = "/"로 시작하고 "//"로 시작하지 않는 내부 경로)
- 로그아웃: POST /logout → session.invalidate() → 목록(/)으로 이동
- 세션 유지시간 30분
- 헤더에 로그인 상태 표시: 비로그인 "로그인 | 회원가입", 로그인 "닉네임님 | 로그아웃"
- 이미 로그인한 사용자가 /login 에 접근하면 목록(/)으로 이동

예외 상황
- 이메일 또는 비밀번호 불일치 시 같은 로그인 폼을 다시 보여주고(이메일 값 유지)
  "이메일 또는 비밀번호가 올바르지 않습니다" 표시 (어느 쪽이 틀렸는지 알려주지 않음)
- 이메일/비밀번호 빈 값이면 필드별 "이메일을 입력해주세요" / "비밀번호를 입력해주세요"

완료 조건
- [ ] 로그인 필요 페이지 접근 시 로그인 페이지로 이동하고, 로그인 후 원래 페이지로 돌아온다
- [ ] 세션에 비밀번호가 저장되지 않는다
- [ ] 로그아웃은 POST 요청으로만 동작하고, 로그아웃 후 로그인 필요 페이지에 접근할 수 없다

## F-03 게시글 목록
유저 스토리: 방문자로서, 최근 글들을 훑어보고 싶다.

상세 동작
- 최신순(id 내림차순), 페이지당 10개
- 표시 항목: 번호, 제목, 댓글 수, 작성자 닉네임, 작성일(yyyy-MM-dd), 조회수
- 하단 페이지 번호 (최대 5개씩 표시, 이전/다음)
- 로그인 시에만 "글쓰기" 버튼 표시

SQL 처리
- 목록은 post + member JOIN, 댓글 수는 서브쿼리로 한 번의 쿼리로 가져온다
- 페이징은 LIMIT ? OFFSET ? 사용, 전체 개수는 별도 COUNT 쿼리

완료 조건
- [ ] 글이 0개면 "등록된 글이 없습니다" 표시
- [ ] 음수나 범위를 넘는 페이지 번호 요청 시 에러 없이 처리 (음수는 0으로, 초과는 빈 목록)
- [ ] 목록 한 페이지를 그리는 데 쿼리는 2번(목록 1 + COUNT 1)만 실행된다

------------------------------------------------------------

## F-04 게시글 상세
상세 동작
- 표시: 제목, 작성자, 작성일, 수정일(수정된 경우), 조회수, 본문, 댓글 목록
- 상세 진입 시 조회수 +1 (UPDATE post SET view_count = view_count + 1 WHERE id = ?)
- 작성자 본인에게만 "수정", "삭제" 버튼 표시
- 본문 줄바꿈 유지, HTML 태그는 이스케이프 (th:utext 사용 금지)

예외 상황
- 존재하지 않는 글 ID → 404 에러 페이지

------------------------------------------------------------

## F-05 게시글 작성
검증 규칙
- 제목: 필수, 공백만 불가, 1~100자
- 본문: 필수, 공백만 불가, 1~5000자

완료 조건
- [ ] 작성 성공 시 해당 글 상세 페이지로 이동 (INSERT 후 KeyHolder로 생성된 id 획득)
- [ ] 작성자는 로그인한 회원으로 자동 설정된다 (폼에서 받지 않음)

------------------------------------------------------------

## F-06 게시글 수정
- 기존 제목/본문이 채워진 폼 제공, 검증 규칙은 F-05와 동일
- 성공 시 상세 페이지로 이동, updated_at 갱신

예외 상황
- 작성자가 아닌 사용자가 수정 페이지 접근 / 수정 요청 시 403 에러 페이지
- 수정 대상 글이 없으면 404

------------------------------------------------------------

## F-07 게시글 삭제
- 상세 화면에서 "삭제" 클릭 → 확인창 → 삭제 후 목록으로 이동
- 글 삭제 시 해당 글의 댓글도 함께 삭제 (FK ON DELETE CASCADE)
- 작성자가 아니면 403

------------------------------------------------------------

## F-08 댓글 작성
- 상세 화면 하단 입력창, 로그인 시에만 표시
  (비로그인 시 "로그인 후 댓글을 작성할 수 있습니다" 문구와 로그인 링크)
- 내용: 필수, 공백만 불가, 1~500자
- 작성 후 같은 상세 페이지로 돌아온다
- 댓글은 작성순(오래된 순) 정렬
- 없는 글에 댓글 요청 시 404

------------------------------------------------------------

## F-09 댓글 삭제
- 댓글 작성자 본인에게만 "삭제" 버튼 표시
- 작성자가 아니면 403
- 댓글이 URL의 글(postId)에 속하지 않으면 404
